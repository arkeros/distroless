# distroless

Bazel-defined OCI base images, the supply-chain evidence attached to them, and
the public mirror they are served from. This file fixes the words used across
those three, so the same idea is not called three things.

## Language

### Images

**Base image**:
An image built here for others to build **on top of**. It holds a runtime and
its dependencies, never an application.
_Avoid_: distroless image (everything here is one — it does not distinguish),
parent image

**Family**:
One kind of base image, addressed by name on the mirror — `static`, `cc`,
`bash`, `nginx`, `java`, `node`, `python`. A family is what a consumer picks.
_Avoid_: image (ambiguous between the family and one built artifact), flavor

**Distro**:
The package universe a **Family** is assembled from — `debian` or
`hummingbird`. It decides where packages come from and, through `ID` in
`/etc/os-release`, which security database a scanner routes findings to.
_Avoid_: base OS (there is no OS running), distribution (overloaded with
**Mirror**)

**Variant**:
One cell of the matrix a **Family** publishes: **Distro** × **User** × debug ×
architecture. Two variants of a family differ in what is inside them, never in
what they are for.
_Avoid_: flavor, tag (a tag names a variant, it is not one), build

**User**:
The identity a **Variant** runs as — `root` (UID 0) or `nonroot` (UID 65532).
_Avoid_: uid (that is the number, not the choice)

**Debug variant**:
A **Variant** with busybox layered on, so there is a shell to exec into. Its
non-debug sibling has none, which is the point of it.
_Avoid_: dev image, fat image

**Index**:
The multi-arch OCI image index a tag resolves to; the per-architecture
manifests hang off it. This is what gets signed, and what a **Digest** names.
_Avoid_: manifest list (the v2 name), manifest (that is one architecture)

**Digest**:
The content address of an **Index**. The only durable name for an image —
every signature and attestation binds to it, never to a tag.
_Avoid_: sha, hash, id

### Provenance

**Lockfile**:
The resolved, checked-in package set a **Distro** builds from —
`debian.lock.json`, `hummingbird.lock.json`, the nginx locks. Regenerated by
`knife`, never edited by hand. It is why building an old commit today produces
what that commit described.
_Avoid_: manifest (that is the input it resolves), pin file

**SBOM**:
The CycloneDX document listing every **Component** in an **Index**. Attached to
the image as an attestation, not merely written to a file.
_Avoid_: bill of materials (spell it out or use the acronym, not both), package
list

**Component**:
One entry in an **SBOM** — a package, with a purl and possibly a `cpe`.
_Avoid_: dependency (implies a build edge that a component need not have),
package (a component may be an upstream tarball, not a package)

**Routable**:
Said of a **Component** a scanner can actually look up: its purl prefix matches
a scanner ecosystem, or it carries a `cpe`. An unroutable component is not
scanned — it is skipped, silently.
_Avoid_: scannable, supported

**Silent zero**:
A clean scan that is clean because nothing was **Routable**, not because
nothing is vulnerable. The failure mode the whole gate exists to prevent: a
report that looks like evidence and is an absence of it.
_Avoid_: false negative (that implies the scanner looked and was wrong; here it
never looked)

**Gate**:
A test that stands between an image and publication. There are three, and they
fail for different reasons: findings, suppressions that no longer match, and
**Silent zero**.
_Avoid_: check, lint, validation

**VEX statement**:
A published, dated claim that a specific CVE does not affect a specific
product, with a justification. It silences a finding **on the record**, unlike
an ignore list.
_Avoid_: exception, waiver, ignore

**Expiry**:
The date a **VEX statement** stops being accepted — at most 90 days out, and
enforced at scan time. It makes a silencing decision a debt with a due date
rather than a permanent settlement. A local extension; OpenVEX has no such
field.
_Avoid_: TTL, review date (nothing merely reminds you — the build fails)

**Stale suppression**:
A **VEX statement** or wontfix entry that no longer matches anything in the
scan. Failed on, because a suppression outliving its finding is how an
unrelated future CVE gets silenced by accident.
_Avoid_: unused ignore, dead entry

**SLSA provenance**:
The Bazel-built predicate attached to a **Digest** describing what was built
and from what source. Complements the signing certificate: the certificate
carries runtime fidelity (which workflow ran), the predicate carries
build-graph fidelity (what it built).
_Avoid_: GHA provenance (it is build-derived, not CI-derived), build info

**Attestation**:
A signed predicate bound to a **Digest** — **SLSA provenance** or **SBOM** —
attached over the OCI 1.1 referrers API.
_Avoid_: metadata, annotation (those are unsigned and live in the manifest)

### Distribution

**Mirror**:
The public surface, served at `distroless.io/<family>` and backed by GHCR.
Every image on it is the published contract of the project; anything attached
to it is part of what a consumer verifies.
_Avoid_: registry (that is the **Registry** below), public images (too broad —
not everything public is on the mirror)

**Mirror push**:
The macro that publishes to the **Mirror**, wrapping push, sign and attest into
one unit. It is the *only* path onto that surface, which puts the "everything
published is signed and attested" policy in the build graph instead of in CI
script discipline.
_Avoid_: image_push to GHCR (that is the primitive underneath), publish step

**Deploy path**:
The Artifact Registry copies of images Cloud Run pulls at deploy time. Same
**Digest** as the mirror copy, different registry, and trusted by IAM rather
than by signature — so it is deliberately outside **Mirror push**.
_Avoid_: private mirror (it is a deploy substrate, not a mirror), GAR images

**Registry**:
The pull-through proxy serving `distroless.io`, and the one thing in this repo
that is an application rather than a base image.
_Avoid_: mirror (that is the surface it serves), proxy (too generic — it
implements the OCI distribution pull API)

**Verification perimeter**:
The consumer's own infrastructure, where verification actually happens. This
project's job ends at publishing a stable identity policy and the signed
evidence; nothing verified internally substitutes for a consumer verifying.
_Avoid_: CI verification (that guards this repo, not a consumer)

## Relationships

- A **Family** publishes many **Variant**s; a consumer picks a family and a tag,
  and the tag resolves to one **Index**
- A **Variant** is a **Distro**, a **User**, a debug choice and an architecture
  — nothing about what the image is *for*
- A **Distro** is materialised by a **Lockfile**, and announces itself through
  `ID` so a scanner routes findings to the right database
- An **Index** has one **SBOM**, listing **Component**s; a component is either
  **Routable** or invisible to scanning
- The three **Gate**s fail on findings, on **Stale suppression**s, and on
  **Silent zero** — the last one is why an empty report is not evidence
- A **VEX statement** silences a finding until its **Expiry**; after that the
  gate fails again and the claim must be remade
- **Mirror push** binds the signature, the **SLSA provenance** and the **SBOM**
  to a **Digest**, and is the only way onto the **Mirror**
- The **Deploy path** shares the digest but not the trust model, so it uses a
  plain push
- The **Registry** serves the **Mirror**; it is itself published to the mirror,
  and its own deploy copy travels the **Deploy path**

## Example dialogue

> **Dev:** "The scan came back clean, so the image is clean."
> **Domain expert:** "It came back with no findings. Whether that is evidence
> depends on whether the **Component**s were **Routable**. A `pkg:generic`
> tarball has no matcher, so grype reports nothing about it — not that it is
> fine, but that it never looked."
> **Dev:** "How would I tell those two apart?"
> **Domain expert:** "You wouldn't, from the report — that is the whole problem,
> and it is why we call it a **Silent zero** rather than a false negative. A
> false negative means the scanner looked and was wrong. So there is a **Gate**
> that lists every unroutable component and fails if the list is not the one we
> already accepted."
> **Dev:** "And the CVE we decided not to fix — I'll add it to the ignore list?"
> **Domain expert:** "Add a **VEX statement**. An ignore list says a number is
> uninteresting; a VEX statement says why this CVE does not affect this product,
> signed and dated, and consumers can read it."
> **Dev:** "Dated meaning it stops working?"
> **Domain expert:** "In 90 days at the latest. A silencing decision is a debt
> with a due date. **Expiry** is ours, not OpenVEX's — the spec has no way to
> say it."
> **Dev:** "What if the CVE gets fixed upstream before then and the statement
> stops matching anything?"
> **Domain expert:** "Then it is a **Stale suppression** and the build fails on
> it. It has to — a statement that matches nothing today is sitting there
> waiting to silence some unrelated CVE that happens to reuse the identifier
> later."
> **Dev:** "Fine. Can I push a one-off build to GHCR to test something?"
> **Domain expert:** "Not to the **Mirror**. The only path there is **Mirror
> push**, so that everything on that surface is signed and attested by
> construction rather than by everyone remembering. The **Deploy path** is
> different — same **Digest**, IAM trust instead of signatures, plain push."

## Flagged ambiguities

- "image" was used for a **Family**, for a **Variant**, and for an **Index** —
  resolved by the three terms. A consumer pulls a family, gets an index, and
  what varies between indexes is the variant.
- "distroless" was both the project and an adjective for every image in it —
  resolved: it names the project. Use **Base image** for the thing.
- "ignore" covered wontfix entries and VEX statements as though they were one
  mechanism — resolved: a **VEX statement** is published and has an **Expiry**;
  a wontfix entry is neither, and is only for findings we have accepted
  permanently.
- "mirror" was used for the public surface and for the GAR copies — resolved:
  GAR is the **Deploy path**, and calling it a mirror hid that it carries a
  different trust model.
- "debug" read as a build configuration, like a debug compile — resolved: a
  **Debug variant** differs by containing busybox, nothing else. The
  application bytes are identical.
